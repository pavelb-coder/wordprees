# Удаление папки отчётов из экспорта — 1.0.11

## Что меняется

Новый полный экспорт и скачиваемый комплект ZIP не содержат папку `отчёты/`: основной протокол, задания и индивидуальные попытки сохраняются. Отдельный экспорт вопросов не запускает удаление отчётов. Изменение не удаляет прежние копии протоколов.

По явно подтверждённому выбору владельца после **успешной полной записи** нового комплекта удаляются только три точных пути в `отчёты/`:

- `манифест_выгрузки_<имя текущей олимпиады>.txt`;
- `руководство_к_протоколам.txt`;
- `сводка_результатов.txt`.

Общие два файла могли принадлежать другой олимпиаде, а любой из трёх мог содержать ручные правки — при необходимости заранее сохраните копии. Манифесты других олимпиад с другими именами, собственные файлы, вложенные папки, файлы в корне/import и другие каталоги не удаляются. Переименование олимпиады может оставить манифест со старым именем.

На локальном/примонтированном диске, SMB и FTP пустой каталог удаляется нерекурсивно; если в нём остаются другие данные, каталог сохраняется и интерфейс сообщает об этом. В WebDAV сами три файла удаляются, но каталог намеренно остаётся: WebDAV DELETE каталога является рекурсивным и может удалить скрытые или добавленные одновременно файлы. Если каталог действительно пуст, организатор может удалить его вручную.

Очистка не запускается при проверке подключения, размещении редактора, скачивании ZIP или неполной записи нового комплекта. При отказе очистки интерфейс показывает ошибку; для автоматической выгрузки ошибка сохраняется в настройках олимпиады до успешной очистки (не более 30 дней), не прерывая сдачу участника. Часть нового экспорта и уже удалённых отчётов может существовать, поэтому после исправления прав операцию можно повторить. Не используются маски или рекурсивное удаление. Локальная ссылка на каталог отвергается, ссылка на файл удаляется как ссылка. FTP требует подтверждения типа объекта через MLSD и LIST, SMB — readlink/allinfo; если сервер не может подтвердить безопасность, очистка прерывается. WebDAV проверяет тип файла через PROPFIND и требует сильный ETag для условного DELETE без редиректов. Сервер сетевого хранилища должен честно применять эти механизмы и не перенаправлять пути на чужие каталоги.

## Проверки на изолированном стенде

WordPress 7.1.3, PHP 8.4.27, MariaDB 11.8.6. **151/151 интеграционных тестов**, включая 141–151: отсутствие папки в комплекте, точный объём и последовательность удаления, чужие файлы и другая олимпиада, повтор, сбой записи, symlink/каталог с именем файла, автоматическая сдача и видимость ошибок её очистки, отсутствие очистки при тестовом соединении и экспорте вопросов, безопасность WebDAV, отказ при отсутствии ETag и конфликте версии файла.

Проверены реальные локальные соединения filesystem, WebDAV, FTP и SMB: удаление трёх старых файлов, отсутствие каталога на пустом диске/FTP/SMB, сохранение непустого каталога, отсутствие каталога у новой выгрузки, повтор и сохранность старых протоколов. Для диска/FTP/SMB проверены ссылки на каталог и файл; WebDAV-каталог остаётся для безопасного ручного удаления. Выполнены параллельные экспорты на каждом транспорте. HTTP-проверка админской выгрузки подтвердила уведомление о сохранённом чужом файле, отсутствие отчётов в скачанном ZIP и защиту nonce/авторизацией.

Стенд содержит только вымышленные данные. Реальный WordPress и NAS не подключались; установка обновления сама по себе ничего не удаляет. Очистка произойдёт при следующей успешной полной выгрузке.
