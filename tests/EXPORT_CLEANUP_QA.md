# Очистка двух английских экспортных имён — 1.0.8

## Подтверждённый объём

Пользователь выбрал удаление **существующих копий тоже**. После успешной полной записи новой выгрузки удаляются только два точных относительных пути:

- `вопросы/questions.csv`
- `вопросы/questions.json`

Оба режима экспорта создают одинаковый набор из пяти русских файлов: список заданий, правильные ответы, критерии, полноценные вопросы_<имя>.csv / .json. Машинные CSV/JSON остаются доступными для повторного импорта. В import, корне, английском questions/ и любых других папках файлы с теми же именами не удаляются. Удаление не производится при чтении настроек, проверке подключения, размещении шаблонов или редактора.

Старые экспортные дубли, отредактированные вручную, также попадают под явно выбранную очистку — перед следующим экспортом нужен свой backup, если их содержимое важно. Автоимпорт, явно ссылающийся на удалённое экспортное имя, следует переключить на русский файл/свой import-источник. БД вопросов не изменяется.

## Защита и ошибки

- Нет произвольного filename-параметра у cleanup, wildcard или recursive delete. Нет нового публичного удаляющего endpoint.
- Существующие admin AJAX по-прежнему требуют manage_options и nonce; автоматическая выгрузка использует сохранённую администратором конфигурацию.
- Сначала передаётся весь набор. Локальная запись атомарная, FTP проверяет каждый файл/подкаталог, SMB анализирует все NT_STATUS (ошибка раннего PUT не маскируется успешной последней командой).
- DELETE WebDAV не следует redirect, 403/202/301 не считаются удалением, 404/410 считаются отсутствием. Отказ удаления возвращает явную ошибку.
- Локальная ссылка на каталог экспортной папки блокируется до записи. Файл-ссылка с одним из двух старых имён удаляется как ссылка, внешний оригинал не удаляется. Каталог с именем questions.csv/json рекурсивно не очищается.
- Credentials не входят в URL сообщений/логов; SMB использует временный auth-файл 0600 с удалением в finally.
- Повтор и конкурентное удаление отсутствующего файла допускаются; прочие файлы не затрагиваются.

## Проверки

**131/131** тест плагина на WordPress 7.1.3 / PHP 8.4.26 / MariaDB 11.8. Новые 126–131 покрывают файлы/13 типов, точный объём удаления, оба режима/повтор, import/посторонние файлы, symlink/каталоги, порядок PUT→DELETE и ошибки WebDAV. Прежние roundtrip-тесты обновлены на русские машинные файлы.

**60/60 реальных HTTP/браузерных/транспортных проверок** Chromium/Playwright, PHP-server, Samba 4.22, pyftpdlib и строгого WebDAV:

- Отдельный и полный экспорт на filesystem, WebDAV, FTP и SMB: существующие два английских файла физически отсутствуют, пять русских файлов существуют; import/questions.csv/json, корневые questions.csv/json, посторонняя questions/foreign.json, проект и методичка побайтово сохраняются.
- Повтор работает, когда старых имён уже нет.
- Русские CSV/JSON прочитаны обратно существующими NetworkImport readers через каждый реальный транспорт; в обоих форматах все 13 типов.
- При отказе PUT JSON на DAV/FTP оба старых файла сохраняются. Отказ DELETE JSON даёт ошибку; повтор после восстановления прав завершает очистку.
- Настоящий SMB: неуспешный ранний PUT при успешном последнем обнаруживается, старые файлы не удаляются; отказ прав удаления видим; восстановление работает.
- Два одновременных экспорта на каждом из четырёх транспортов успешны, идемпотентны и сохраняют все защищённые файлы.
- Неверный nonce и anonymous AJAX не могут запустить очистку.
- SHA-256 строк таблицы вопросов до/после совпадает; .wpo-export-* временные файлы не остаются; исключений JS нет.
- Локальные действия выполнены настоящими кнопками настроек, остальные — аутентифицированными HTTP-действиями тех же handlers.

Итоговый ZIP устанавливается и полный набор/транспортные проверки повторяются. Source/ZIP/установленный экземпляр сверяются побайтово, Windows-editor assets и Excel-шаблон не изменяются. Серверы, passdb/учётные записи, управляющие файлы, реальные NAS-данные, SQL, cookies, логи и screenshots не входят в поставку/Git. Production сайт/NAS не подключается: очистка на нём выполнится после установки и следующего успешного экспорта.
