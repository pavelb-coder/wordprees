# Авто-выгрузка без файлов заданий — 1.0.14

> **С 1.0.16 кнопки выгрузки вопросов и файлов `вопросы/` в выгрузках нет** — экспорт вопросов удалён из плагина, а ранее созданные файлы снимаются точечно после успешной выгрузки. Ниже — описание 1.0.14 (история).

## Что меняется

Файлы заданий в `вопросы/` больше не входят в **автоматическую** выгрузку, которая запускается при сдаче теста участником (`network_auto_export`). Автоматический комплект содержит только `протоколы/протокол_<имя>.csv` и `попытки/попытка_*.csv`. Это подтверждённый выбор владельца: `NetworkExport::export_quiz()` и `generate_export_files()` получили параметр `$include_questions`, путь сдачи через REST передаёт `false`, а ручные вызовы — прежнее значение `true`.

Исключены все пять файлов `вопросы/`: `список_заданий.csv`, `правильные_ответы.csv`, `критерии_и_ответы_<имя>.csv`, `вопросы_<имя>.csv`, `вопросы_<имя>.json`. Проверка и снятие устаревших имён `вопросы/questions.csv` и `вопросы/questions.json` (`QuestionExportCleanup`) при авто-выгрузке **не выполняются**: раз новые файлы заданий не пишутся, удалять старые нельзя.

Задания по-прежнему выгружаются:

- отдельной кнопкой «📤 Экспортировать вопросы в сетевую папку» (`wp_olympiad_export_questions_to_network`, `NetworkExport::export_questions_to_network()`) — ровно пять файлов `вопросы/` и очистка двух устаревших имён;
- ручным **полным** экспортом из страницы «Результаты» (`wpo_action=export_network`) и админским AJAX `wp_olympiad_export_network` — основной протокол, пять файлов заданий и попытки;
- скачиваемым ZIP `file=all` — `download_exported_file()` и `generate_export_package()` вызывают `generate_export_files()` со значением по умолчанию, поэтому состав архива не изменился.

Что осталось без изменений при авто-выгрузке: единство основного протокола (один CSV на олимпиаду, старые копии и протоколы других олимпиад сохраняются), индивидуальные попытки, размещение файлов редактора в `import/`, снятие трёх старых файлов `отчёты/` после успешной записи, сохранение в транзиенте `wpo_last_network_export_<id>` и блоке аудита, поведение при отказе сети (ошибка не прерывает сдачу участника).

Интерфейс: подпись чекбокса — «Автоматически выгружать файлы протоколов и попыток (CSV) напрямую в сетевую папку при каждом завершении тестирования участником», рядом — пояснение, что задания выгружаются отдельной кнопкой и ранее созданные файлы не удаляются. Сообщение результата авто-выгрузки содержит ту же оговорку, а карточка «Последний успешный экспорт» на странице олимпиады показывает, что файлы заданий этой выгрузкой не изменялись. Новый ключ результата — `questions_included`.

**Практическое следствие:** после правки набора заданий нажмите кнопку «Экспортировать вопросы в сетевую папку» (или выполните полную выгрузку) — раньше `вопросы/` обновлялся при каждой сдаче. Если в хранилище остались `questions.csv`/`questions.json`, они не удалятся, пока не будет выполнена выгрузка заданий; автоимпорт, ориентированный на эти имена, продолжает видеть прежние файлы.

## Проверки на изолированном стенде

WordPress 7.1.3, PHP 8.4.27, MariaDB 11.8.6. `tests/test-suite.php`: **168/168** на исходниках и на распакованном установочном ZIP. Новые проверки 163–168:

- авто-пакет не содержит `вопросы/`, состав `протоколы/` и имя основного протокола прежние, попытка выгружена, сообщение ссылается на отдельную кнопку;
- существующие `вопросы/список_заданий.csv`, `questions.csv`, `questions.json`, `вопросы_<имя>.csv` и ручная заметка сохраняются побайтово и по времени изменения, `removed_legacy_files` пуст;
- реальная сдача через REST (`handle_start` + `handle_submit`) создаёт один CSV в `протоколы/` и один в `попытки/`, не создаёт `вопросы/` и `отчёты/`;
- ручная полная выгрузка даёт семь файлов (протокол, пять `вопросы/`, попытка), убирает два устаревших имени, кнопка заданий возвращает `files_count = 5`, а `generate_export_package()` содержит `вопросы/`;
- при авто-выгрузке без заданий редактор размещается в `import/`, старый `отчёты/манифест_выгрузки_<имя>.txt` снимается, чужой файл и непустая папка сохраняются;
- тексты админки и сигнатура `export_quiz(..., bool $include_questions = true)` соответствуют новому поведению, вызовы очистки старых имён вопросов защищены флагом.

Реальные транспорты (`WPO_TRANSPORT=local|ftp|smb|dav`, тестовые серверы в изолированной среде) — **115 проверок, 0 отказов**, выполнены и на исходниках, и на распакованном установочном ZIP — filesystem 29, pyftpdlib FTP 29, Samba/smbclient 29, WsgiDAV 28. Для каждого транспорта: успешная авто-выгрузка с `questions_included = false`, один обновляемый основной протокол при сохранённом старом `сводный_протокол.csv`, каталог `вопросы/` без новых файлов и с неизменными данными, повтор авто-выгрузки, затем кнопка заданий (пять файлов, удаление `questions.csv`, чужая копия цела), ручной полный экспорт (пять `вопросы/`) и третья авто-выгрузка, которая не перезаписала выгруженные задания. На filesystem/FTP/SMB дополнительно проверено снятие старого файла отчёта; в WebDAV пустой каталог `отчёты/` остаётся по-прежнему (DELETE каталога там рекурсивен).

Реальные HTTP-запросы к тестовой админке (на установленном ZIP): сдача участника через REST, страница олимпиады с новой подписью и карточкой последней выгрузки, AJAX кнопки заданий, ссылка полного экспорта и скачивание ZIP. Проверено: `протоколы/протокол_<имя>.csv` содержит обоих участников двух сдач, `попытки/` пополняется, `вопросы/` после второй авто-выгрузки не изменился ни по содержимому, ни по времени, ZIP содержит `протоколы/`, пять `вопросы/` и `попытки/` без `отчёты/`. В логе PHP-сервера нет warning/notice/fatal. Синтаксис: `php -l` по всем 50 PHP-файлам и `node --check admin/js/admin.js`.

## Запуск своего регрессионного теста

```sh
wp --path=/path/to/test-wordpress eval-file /path/to/wp-olympiad/tests/test-suite.php
```

Запускайте suite **только на отдельной тестовой установке WordPress**: он создаёт и удаляет тестовые олимпиады, попытки и записи настроек. Стенд содержал только вымышленные данные; реальный сайт и NAS не подключались. Установка 1.0.14 сама по себе ничего не удаляет из `вопросы/`: изменение проявляется только при последующих выгрузках.
