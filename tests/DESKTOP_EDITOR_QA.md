# Интеграция редактора Windows — проверка 18.10.2026

> Историческая проверка прежней версии. С 1.0.12 в сетевую `import/` размещаются только EXE и исходники; размещение шаблона отключено. См. `IMPORT_FOLDER_QA.md`.

## Стенд

WordPress 7.1.3, PHP 8.4.26, MariaDB 11.8, Chromium 156 (Playwright). Локальные серверы Samba, FTP (pyftpdlib) и WebDAV с Basic Authentication. Файлы не отправлялись на внешние пользовательские серверы.

## Результаты

### Плагин: 88 / 88

Команда из каталога плагина:

```bash
wp eval-file tests/test-suite.php --path=/путь/к/wordpress
```

Новые тесты 81–88 (`test-desktop-editor.php`):

- Манифест, allow-list, размер и SHA-256 пяти assets, ZIP-структура и отказ при повреждении комплекта.
- Только четыре именованных файла в сетевой `import/`, сохранность вопросов и .wpoq, повторная проверка без перезаписи, восстановление удалённых / повреждённых локальных файлов.
- Нет `import/import`; корректные UNC / URL / локальные пути, в том числе `/mnt/share` и имя «Василий». Блокировки, частичная локальная запись, retry, защита от symlink.
- Реальный минутный воркер при выключенном автоимпорте / отложенном чтении вопросов; ручной импорт и успешная проверка подключения автоматически размещают редактор. Сохранение новой / существующей конфигурации также проверено браузером.
- WebDAV: MKCOL, PUT с сохранением разделителей URL и авторизацией, кеш, инвалидация комплекта, повтор после сбоя, отсутствие ложного успешного статуса при HTTP 507/403.
- Шаблоны / экспорт не удаляют существующие кириллические файлы, проекты, ответы или пользовательскую папку questions.
- Административные права, nonce, AJAX, защищённые ссылки, панели в настройках / конструкторе / импорте, отсутствие возвращённого экспорта заданий в конструкторе, обновление JS/CSS-кеша.

### Реальные сетевые передачи: 35 / 35

На локальных серверах **SMB, FTP и WebDAV** для каждого протокола:

- Переданы все четыре файла, SHA-256 совпадает с комплектом плагина.
- Повторное фоновое обращение не перезаливает бинарные файлы.
- Пароль не появляется в сохранённом состоянии размещения.
- Искусственный запрет третьего файла не считается успешной установкой; есть задержка повтора и восстановление по явной команде.
- Проверка подключения действительно автоматически размещает редактор.

Дополнительно: FTP с реквизитами в URL, создание отсутствующих каталогов, подключение прямо к import без вложения import/import и исключение реквизитов из сохранённого destination.

### Браузер / HTTP: 26 / 26

- Новая и изменённая конфигурация: размещение при сохранении даже без автоимпорта вопросов.
- Автоматическое размещение по проверке подключения без сохранения формы, статус и дополнительное восстановление удалённого EXE.
- Реальные скачивания EXE / переносимого ZIP / исходников из админки: имена и SHA-256 совпадают.
- Некорректный nonce — HTTP 403; анонимные запросы не получают файл / не размещают программу; повреждённый bundled EXE — HTTP 503.
- Сканирование видит экспортированный XLSX, но не EXE / ZIP / TXT / .wpoq.
- Через настоящий интерфейс импортированы XLSX из сети, CSV и JSON с ПК, созданные ранее проверенным Windows EXE: по 13 типов, всего **39 заданий в БД, у всех show_points=0**.
- Исходные файлы вопросов, черновиков и ответов на диске неизменны.
- Панель помещается в мобильный экран 390px; JavaScript-ошибок нет.

## Границы проверки

Физический Windows-ПК, конкретные модели NAS, FTPS и HTTPS с нестандартными сертификатами в этой интеграционной проверке не использовались. Предыдущие GUI-проверки EXE выполнены под Wine, не на физическом Windows. Цифровой подписи нет. Периодичность фоновой работы зависит от действующего WP-Cron; удалённые успешные размещения кешируются, а повторная проверка подключения / дополнительная кнопка выполняют принудительную передачу. Внешние пользовательские файлы при удалении плагина не очищаются.
