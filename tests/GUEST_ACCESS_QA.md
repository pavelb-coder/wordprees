# Гостевое участие без WordPress-аккаунта — 1.0.5

## Исправление

Ранее в форме не было поля allow_guest, но обработчик всегда сохранял `!empty(POST[allow_guest])`, превращая отсутствие поля в запрет. Теперь в регламенте есть явный checkbox «Участие без регистрации и входа на сайт» и отдельный маркер его присутствия. Отсутствие обоих полей в старой/частичной форме означает сохранение режима, а не 0. Новые олимпиады сохраняют default=1; явное выключение учитывается. Неподходящие массивы/значения не меняют доступ.

Сохранённый запрет 0 не мигрируется в открытый режим: организатор включает checkbox для нужной олимпиады и сохраняет. Это устраняет исходное сообщение после явного разрешения, не открывая другие закрытые олимпиады автоматически.

Публичный REST-start теперь соблюдает ту же границу, что страница: при запрете гостям и отсутствии WordPress-аутентификации — 401. Параметры клиента не являются авторизацией. Валидная интеграция с индивидуальным API-ключом по-прежнему может работать без WordPress-аккаунта: только проверенный сервером контекст external/start даёт этот доступ. Публичный /start не принимает такой контекст из тела или заголовка запроса.

## Результаты

**116/116** WP-CLI тестов (WordPress 7.1.3 / PHP 8.4.26 / MariaDB 11.8). Новые 113–116 покрывают нормализацию формы, сохранность старых 0/1, DOM/shortcode обоих режимов, REST-защиту и spoofing, вошедшего участника, валидный API, полноценную гостевую сдачу с user_id=0, контактами/оценкой, draft и будущим расписанием.

**26/26** реальных HTTP/браузерных проверок Chromium/Playwright:

- Создание штатной HTML-формой включает и сохраняет гостевой доступ.
- Старая закрытая олимпиада без пересохранения остаётся закрытой. Страница прямой ссылки, shortcode и REST согласованы; запрос с подложенными allow_guest/user_id/auth-параметрами не обходит ограничение.
- Старая/частичная форма сохраняет как запрет 0, так и разрешение 1. Явное включение убирает исходное предупреждение; явное выключение возвращает защищённый режим.
- **Полный пользовательский сценарий без логина**: открытие анкеты → ввод ФИО/email/организации → нативная кнопка старта → выбор ответа → подтверждение сдачи → результат. Выполнен по прямой ссылке и в реальном iframe на HTTP-странице другого origin, с отдельными пустыми browser contexts.
- Обе гостевые попытки сохраняют user_id=0, score=2 и контакты. Число пользователей WordPress не увеличивается.
- Вошедший участник с правильным WordPress REST nonce может начать закрытую олимпиаду.
- External/start отклоняет отсутствие/неверный ключ и принимает проверенный ключ. Заголовок ключа на публичном /start не заменяет выбранный режим доступа.
- Новый контрол помещается в 390 px; исключений JS нет.

Оpaque about:blank не используется как «внешний сайт»: CSP frame-ancestors * не обязан разрешать непрозрачный origin. Положительный iframe-сценарий проверен с настоящим HTTP-родителем; production CSP ради теста не ослаблялась.

Итоговый ZIP устанавливается и проверяется повторно. Источник, ZIP и установленный экземпляр сверяются побайтово; Windows-редактор и Excel-шаблон не меняются. Логи, SQL, тестовые серверы, браузерные сессии и сгенерированные API-ключи в ZIP/Git не входят. Production сайт/NAS не подключаются. После установки пользователь включает новый checkbox для уже заблокированной олимпиады; массовое открытие старых олимпиад не выполняется.
