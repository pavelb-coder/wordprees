# Регламент олимпиады: расписание, обход и формат даты — 1.0.18

Документ описывает исправление карточки «Регламент и расписание олимпиады» и все проверки этой правки. Поведение олимпиад **без** заданного времени не изменилось.

## Что было не так (замерено на стенде)

1. **Обход регламента был незаметен.** `Quiz::is_active_now()` и `Quiz::can_user_attempt()` первыми строками возвращали «всё разрешено» для любого, у кого есть `manage_options`. Замер: при `end_time` в прошлом гость получал `quiz_inactive`, а залогиненный администратор — открытую форму и успешный `POST /start`. Отсюда симптом «время задал, а вовсе ничего не блокирует»: проверка выполнялась на другом аккаунте/в другой вкладке.
2. **Нераспознанная дата молча снимала ограничение.** `new DateTimeImmutable($raw, $tz)` в `try/catch` с пустым `catch`: `10/11/2026 18:00` PHP читал как месяц/день (ноябрь 10), `2026.11.10` — как «now», `31 12 2026` — как «now». Исключение проглатывалось, расписание переставало влиять на что-либо, в интерфейсе об этом не сообщалось.
3. **Дата без времени означала полночь.** `end_time = 31.12.2026` закрывал приём с 00:00 31 декабря — то есть «на день раньше», чем ожидает организатор.
4. **Сдача начатой работы обнулялась.** `RestApi::handle_submit()` → `AntiCheat::validate_submission_time()` звал тот же `is_active_now()`: как только наступал `end_time`, сдача получала `time_expired`, а попытка — `complete(0.0, …, 'expired')`. При этом `process_heartbeat()` в этот момент отвечал `status: ok` с остатком личного таймера. Участник, начавший за 2 минуты до окончания, терял работу.
5. **Подпись «(МСК») врала.** Формы и сообщения участника обещали МСК, хотя сравнение всегда шло по **часовому поясу сайта**. На сайте с `Europe/Krasnoyarsk` «18:00» в поле означало 13:00 МСК.
6. **Участник не видел расписания.** Время начала и окончания нигде на странице олимпиады не показывалось: «когда можно» приходилось угадывать. `count` попыток для администратора всегда был 0 («вы использовали 0 из 1»), а при `show_results_mode = after_end` в REST-ответе печаталось сырое `Y-m-d H:i:s` из настроек.

## Что изменилось

### `Quiz::is_active_now(bool $strict = false)`

Возвращает `['active', 'reason', 'code', 'admin_preview', 'blocked_reason'?]`, где `code ∈ {'', 'not_published', 'before_start', 'after_end'}`. Блокировка считается один раз по `schedule_boundaries()`; её обходят и текст причины, и код. Организатор (`manage_options`) по-прежнему получает доступ к закрытой олимпиаде, но обход:

* помечен `admin_preview => true` и сопровождается `blocked_reason` — текстом, который увидел бы участник;
* отключается настройкой `rules_strict_for_admins` и параметром `?wpo_as_participant=1` (`Quiz::allows_organizer_bypass()`).

`$strict = true` оценивает регламент полностью, как для участника, — так работают предпросмотр и `handle_submit`.

### `Quiz::schedule_boundaries()`

`['tz' => часовой пояс сайта, 'start' => ?DateTimeImmutable, 'end' => ?DateTimeImmutable]`. Значение, которое нельзя разобрать, игнорируется (строки старых выпусков могли содержать что угодно), но форма с 1.0.18 такое сохранить не даёт.

### `Quiz::normalize_schedule_time($raw, $end_of_day = false)`

Канонизирует ввод: `ГГГГ-ММ-ДД[ ЧЧ:ММ[:СС]]`, `ГГГГ-ММ-ДДTЧЧ:ММ`, `ДД.ММ.ГГГГ[ ЧЧ:ММ]`. Формат со слэшами, `ГГГГ.ММ.ДД`, пробельные разделители, несуществующие даты (`2026-02-30`), `24:00`, `10:75` → `null` (значение непригодно). `''` → `''`. Дата без времени → `00:00`, для окончания — `23:59`. Секунды отбрасываются, т. к. настройки хранят `Y-m-d H:i`.

`Admin::save_quiz()` применяет её к `start_time`/`end_time`: пригодное значение сохраняется в каноне, `null` — ключ снимается из `$data['settings']` (прежнее значение остаётся) и редирект получает `&schedule_error=<поле>`; `notice notice-warning inline` выводится над полями в `admin/views/quiz-edit.php`. Тот же редирект передаёт и `link_alias_error` — оба кода собраны в один `add_query_arg()`.

### `AntiCheat::validate_submission_time(Attempt, Quiz, bool $strict = false)`

При `code === 'after_end'` сдача принимается, если `started_at <= окончания приёма` (`started_within_window()`; сравнение в часовом поясе сайта, как и запись `current_time('mysql')`). Нет `end_time` — принимается. `time_limit` с grace 45 с, `not_published` и `before_start` блокируют как раньше; `handle_submit` по-прежнему помечает попытку `expired` только при genuine истечении личного таймера.

### Предпросмотр «глазами участника»

`Quiz::is_participant_preview()` — `?wpo_as_participant=1` **только для администратора** (иначе параметр не действует). Используется в `Shortcodes::render_quiz()` (строгий рендер + предупреждение), в `RestApi::handle_start()` (`is_active_now($strict)`, `can_user_attempt(…, $strict)`) и в `handle_submit()`. Ссылки «Проверить глазами участника» / «Вернуть обычный вид» строит `Shortcodes::participant_preview_url()`: на записи — по `get_permalink()`, на прямой ссылке — по `?wpo_runner=<имя|номер>`.

### Настройки и вывод

* `rules_strict_for_admins` (по умолчанию `0`) — чекбокс «Строгий регламент» в карточке регламента; `Quiz::rules_strict_for_admins()`.
* `Quiz::schedule_timezone_label()` — `МСК`, `UTC` или `Азия/Красноярск (UTC+7)`; подписывает поля формы, сообщение о незапущенной олимпиаде, строку «Часовой пояс: …» и дату в ответе `after_end`.
* `Shortcodes::schedule_meta_lines()` — «Начало: ДД.ММ.ГГГГ ЧЧ:ММ», «Приём ответов до: …», «Часовой пояс: …» в мета-гриде стартовой страницы; пустой вывод, если расписание не задано.
* `can_user_attempt()` возвращает настоящий `count` и для администратора, `admin_preview` при обходе, `blocked_reason`; предупреждение «Лимит попыток для вас не применяется…» показывается на странице.
* Под полем лимита попыток — сноска: у гостя попытки считаются по e-mail, поэтому при выключенном или необязательном e-mail лимит его не остановит (это прежнее поведение, о котором раньше не сообщалось).

## Совместимость и границы

- Олимпиады с пустыми `start_time`/`end_time` работают точно как раньше: `active => true`, предупреждений нет.
- **Поведение администратора по умолчанию сохранено** (иначе организатор потерял бы доступ к своей странице для проверки); изменение в том, что обход виден, цитирует причину участника и отключается одной настройкой.
- `?wpo_runner=<номер>` и именованные ссылки 1.0.17 не затронуты: `handle_standalone_runner()` резолвится до оценки регламента, предпросмотр добавляет только свой параметр.
- Формат хранения не менялся (`Y-m-d H:i` в настройках олимпиады), миграций и новых колонок нет; `rules_strict_for_admins` отсутствует в старых записях → `get_setting(..., 0)` = прежнее поведение.
- Нераспознанные значения, записанные до 1.0.18, продолжают игнорироваться (олимпиада открыта) — но стереть или «починить» их нельзя молча: любое сохранение формы либо принимает канон, либо оставляет прежнее значение с объяснением.
- Сообщения участника больше не ссылаются на МСК без основания; тексты шаблонов переводов (`languages/wp-olympiad.pot`) не перегенерированы — как в предыдущих выпусках.

Прежние 182 теста зелёны без изменений.
