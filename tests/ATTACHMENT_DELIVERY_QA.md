# «Вложения участников не скачиваются в сетевую папку» — как это проверяется (1.0.41)

## Что уже доказано живым прогоном

На песочнице с реальной Samba 4.22 (`//127.0.0.1/qa1042`, конфиг `qa/qa-share.conf`) прогон
`qa/probe-real-delivery-1042.php` даёт:

- **доступная шара** → `проба ok`, `недоставлено: 0`, на шаре
  `olimp/вложения/<slug>/Иванов Пётр — 1/Иванов Пётр — 01 — скан работы.pdf` (1096 B),
  повторная доставка тех же файлов ничего не портит, `redeliver` отвечает
  `NT_STATUS_OBJECT_NAME_COLLISION` (файл уже на месте — это успех, а не ошибка);
- **шара «только чтение»** (`//127.0.0.1/qaro`) → `проба ПРОВАЛ` с
  `NT_STATUS_ACCESS_DENIED`, `недоставлено: 1` с той же причиной, событие
  `wpo_attachments_retry` поставлено (`true`), `handle_retry_event()` честно повторяет
  попытку и оставляет `pending: 1`, ответ сервера виден построчно.

Вывод: цепочка «сдача → spool → транспорт на шару → автоповтор → «Доставить сейчас»»
работает. Если у вас файлы не доезжают, причина — в сервере, путях или правах, и она
подписана в самом плагине. Ниже — как её снять целиком одной командой.

## Диагностика на рабочем сервере

```
cd /path/to/wordpress
WPO_DIAG_QUIZ=<id олимпиады> wp eval-file \
  wp-content/plugins/wp-olympiad/tests/diagnose-attachments.php --allow-root
```

Без `WPO_DIAG_QUIZ` скрипт пройдёт по всем олимпиадам (до 100). Он только читает.

На что смотреть в выводе:

| Строка вывода | Что означает |
|---|---|
| `smbclient => NULL` | нечем возить UNC: `apt-get install smbclient` (или `smbclient` из сборки) |
| `disable_functions содержит exec/proc_open?: ДА` | PHP запрещено запускать транспорт — доставка физически невозможна |
| `задания «прикрепить файл»: 0` | ни одно задание не принимает файлы — на шару ехать нечего |
| `проба папки вложений: ПРОВАЛ` | папки `вложения/<slug>` нет, проводить некуда; причина и код сервера в той же строке |
| `недоставлено файлов: N` + `← …` | транспорт попробовал и получил отказ; `share` в списке — куда именно не доехало |
| `отметок «доставлено» > 0`, а на шаре пусто | смотрите не ту папку или меняли путь транспорта (отметки тогда обнуляются по `sig`) |
| `событие планировщика … false` при `pending > 0` | `DISABLE_WP_CRON`/заглушённый cron — автоповтор не запустится, жмите «Доставить сейчас» |
| `upload_max_filesize` / `post_max_size` меньше лимита плагина | файл отсекается до плагина: вложений не будет вовсе, и к шаре это отношения не имеет |

## Куда смотреть на шаре

`<путь из настройки>\вложения\<slug олимпиады>\<Фамилия И. — ID участника>\<Фамилия И. — NN — имя файла>.<расш>`.
В `spool`-режиме (UNC без монтирования, WebDAV, FTP) оригиналы всегда лежат в
`wp-content/wpo-attachments/<slug>/…` — если они есть там и нет на шаре, дело в доставке, а не в приёме.

## Полезно знать про 1.0.41

В спокойном состоянии под полем «Вложения участников» — одна короткая строка с путём папки;
полное объяснение про автоповтор и «Доставить сейчас» показывается только когда есть
недоставленные файлы или проба папки падала. Кнопка «Проверить папку вложений» в поле одна.
