# Результаты без проходного процента — 1.0.7

## Объём

Удалены pass_percentage, show_pass_pct, расчёт/хранение passed, автоматические подписи зачёта/рангов по порогам, плашка порога, классификация в общем/личном результате, CSV, манифесте, API и webhook. Порог не обнуляется, результат не подменяется массовым true/false.

Сохраняются баллы, максимум, процент набранных баллов, правильность отдельных ответов, комментарии, рабочие статусы и ограничения. 0% и 100% — completed; непроверенные задания — needs_review, временные/дисциплинарные статусы сохраняются.

## Миграция и совместимость

Новая таблица попыток не содержит passed. Обновление удаляет прежний столбец и нормализует старые статусы passed/failed в completed, не меняя оценки/ответы. Из JSON-настроек удаляются порог/его показ/старые процентные шкалы. Настройки очищаются ограниченными compare-and-swap пакетами, с продолжением через cron/админку, без перезаписи параллельных данных. Runtime фильтрует старые ключи сразу, независимо от прогресса очистки.

При невозможности ALTER колонка не используется приложением; сохраняется маркер повторного удаления. Данные/ответы не удаляются. Для восстановления прежних настроек перед обновлением нужна резервная копия БД. Исторические файлы в подключённой сетевой папке не стираются автоматически.

Старый позиционный boolean в PHP complete/update_manual_review принимается и игнорируется; get_grade_info возвращает нейтральный label, %GRADE% — статус обработки. Эти совместимые входы не вычисляют прохождение. API/CSV-контракт намеренно изменён: passed, pass_percentage, show_pass_pct, grading_scales, grade_label, feedback_message больше не выдаются. Бинарная колонка Результат удалена, не переименована в всегда-положительный результат.

## Проверки

**125/125** WP-CLI тестов на WordPress 7.1.3 / PHP 8.4.26 / MariaDB 11.8. Новые 119–125 покрывают отсутствие ключей/UI, 0/100, API, ручную оценку/удаление ответа, CSV/манифест, очистку старого retry до HMAC и миграцию без потери данных.

Перед применением создана резервная копия тестовой БД и отдельная legacy-попытка на версии 1.0.6. После обновления подтверждены прежние score=5, percentage=100 и все исходные ответы. Столбец passed удалён. Отдельная свежая установка итогового ZIP проверяет отсутствие устаревшего столбца с самого начала и нормальную сдачу без порога.

**35/35** реальных HTTP/браузерных проверок:

- Новая/существующая HTML-форма без полей и плашки; старые/подложенные POST-значения не возвращают порог.
- В БД принудительно внесены старые 0 и 100 и старая подпись «Не зачёт». Нативный участник получает 0% / 100%, в обоих случаях «Тестирование завершено» и «Завершено», нейтральный score badge. Баллы и заработанный процент отображаются.
- Внешние quiz/result/attempts не содержат retired-полей; прежний pass-only фильтр отклонён с 400.
- Список/детали попыток и личная история используют рабочий статус, в том числе при нулевом результате и ожидании проверки.
- Настоящие CSV скачаны через административные HTTP-действия, проверены заголовки/число колонок и отсутствие классификации.
- Отправка essay даёт needs_review. Частичная HTTP-оценка оставляет pending и 4/10; штатная кнопка утверждает 9/10 completed; удаление ответа пересчитывает 4/10 без проходного сравнения. Неверный nonce даёт 403.
- Реальные test webhook и старый payload с passed/threshold отправлены HTTP-получателю: retired-полей нет, HMAC проверяется получателем на точном body.
- Настоящий сетевой экспорт не содержит числа/доли прошедших.
- 390 px без переполнения, JS-исключений нет. Снимки результата 0% и настроек просмотрены.

Итоговый ZIP устанавливается и тесты повторяются. Источник/ZIP/установленный экземпляр проверяются побайтово. Windows-редактор и Excel-шаблон не менялись. Тестовые серверы, SQL, generated credentials, browser sessions, логи и screenshots в поставку/Git не включаются; production сайт/NAS не подключается. Правильность ответов и пороги конкретного задания (например, допустимая погрешность числа или число ключевых слов) не являются проходным процентом олимпиады и сохранены.
