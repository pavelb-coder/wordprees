# Анкета регистрации и вывод вопросов по группам — 1.0.21

Документ описывает две новые возможности (дополнительные поля стартовой формы и группы вопросов на странице прохождения), их границы и все проверки. Регламент 1.0.18–1.0.20, состав выгрузок и поведение `import/` не изменены.

## Что добавлено

### 1. Дополнительные поля анкеты (`custom_fields`)

* **Где задавать:** «WP Olympiad → Олимпиады → Параметры → ➕ Поля анкеты на стартовой форме» (карточка «Дополнительные поля и группы»). До 10 полей, метка до 120 символов, варианты списков — до 40.
* **Типы:** `text`, `textarea`, `number`, `select`, `multiselect`, `checkbox`, `date`. Для поля: метка, подсказка (`placeholder`), пояснение (`help`), обязательность, максимальная длина, список вариантов.
* **Где хранится:** описания — в JSON-настройках олимпиады (`settings.custom_fields`), значения участника — в новой колонке `wp_olympiad_attempts.participant_meta` (JSON вида `{"fields":{...},"groups":{...}}`). Отдельных таблиц нет, колонка добавляется `dbDelta()` при активации/обновлении.
* **Чистка и валидация:** `ParticipantFields::sanitize_defs()` на записи и на чтении (вызывается из `Quiz::normalize_custom_settings()`, куда попадают `Quiz::__construct()`, `create()`, `update()`, `save_settings()`); `ParticipantFields::clean_values()` — на старте попытки.
* **Проверки на сервере:** обязательные поля, «значение только из списка», число (принимается запятая, storing — точка), дата в двух форматах с `checkdate()`, мультивыбор только из допустимых вариантов (принимается массив, JSON-строка и перечисление через `,`/`;`/перенос строки), чекбокс «да/нет», обрезка по `max_length`. Ошибка — `400 invalid_custom_fields`, текст перечисляет поля человеческими названиями.
* **Куда попадают значения:** `протокол_<имя>.csv` и выгрузка попыток (колонки `Анкета: <метка>`, пустое значение — «—»), индивидуальный CSV работы, блок «Дополнительная анкета» на странице проверки работы, `attempt.custom_fields` webhook-нагрузки, `attempt.custom_fields` REST-описания попытки, параметр `custom_fields` внешнего `POST /external/start`.
* **Чего нет:** писем. `Mailer::send_attempt_emails()` — намеренный no-op с 1.0.3, поэтому «поле в письме участнику/админу» физически добавить некуда; при возврате почты значения отдадутся из `Attempt::custom_field_values()`.
* **Стартовая страница выключена (`enable_intro_page = 0`):** анкета не выводится, не проверяется и не требуется — заполнять её негде.

### 2. Группы (разделы) вопросов и постраничный вывод

* **Группа не дублирует сущность.** Это существующее поле задания `options.group_name` («Раздел / группа» в карточке вопроса, колонки «Раздел/Часть/Блок/Тема/Категория» в Excel-шаблоне). Импорт вопросов не тронут.
* **Настройки групп** — `settings.question_groups`: до 20 записей `{name, title, instruction, time_limit, position}`. `name` сопоставляется с группой заданий независимо от регистра и лишних пробелов (`QuestionGroups::key()`), `title` по умолчанию равен `name`, `instruction` до 1000 символов, `time_limit` в минутах (0 — без лимита, максимум 600), `position` — порядок (0 — по первому появлению). Редактор на странице настроек сам подставляет группы, уже встречающиеся в заданиях.
* **Порядок вывода:** `QuestionGroups::order()` ставит задания одной группы рядом; вопросы без группы идут в начало и сохраняют относительный порядок; при пустых настройках порядок не меняется вообще (обратная совместимость). Перемешивание вопросов работает внутри групп.
* **Постраничный вывод:** `settings.questions_per_page` — 0 (по одному, как раньше) или N (пачками по N, до 50). В раннере `buildPages()`/`renderPage()`, «Назад/Далее» листают страницы, счётчик показывает «N (стр. 2 из 3)», одиночный режим использует прежний код.
* **Баннер группы:** заголовок, инструкция и обратный отсчёт (`wpo-group-banner`, `wpo-group-timer`), показывается над первым вопросом группы на странице.
* **Лимит группы:** считается от момента открытия группы. Первая группа открывается на старте (серверная отметка в `start_attempt`), остальные — при первом просмотре: `POST /heartbeat` с параметром `group` → `Attempt::mark_group_opened()` (повторные отметки существующую не двигают). Клиентский отсчёт только информирует и выключает поля просроченной группы.
* **Что происходит при просрочке:** `RestApi::overdue_group_questions()` + `Grader::grade(..., $locked_questions)` — ответы группы сохраняются, но получают `awarded_points = 0`, `needs_manual_review = 1` и комментарий «Время на группу «X» истекло — ответ сохранён, но не оценивается». `max_score` и остальные группы не меняются, итоговый балл = сумма незачтённого. Обязательные вопросы просроченной группы исключены из проверки `required_question_missing`, то есть работа сдаётся, а не блокируется.
* **Почему «не наказываем без отметки»:** если heartbeat не дошёл (JS выключен, сеть пропала), группа считается неоткрытой и её ответы не обнуляются — лимит не может сработать «задним числом».
* **Видно организатору:** в протоколе заголовок вопроса подписан группой (`Вопрос 1 — Практика: … [Ответ]`), на странице проверки работы у каждого задания бейдж с названием группы, в REST-ответе `/external/attempts` у ответа есть `group_name`.

## Что проверялось только статически

Рендеринг раннера в реальном браузере на этом стенде не запускался — браузер в окружении проверки недоступен. Клиентская логика подтверждена тремя способами: серверным контрактом (REST отдаёт `custom_fields`, `question_groups` и `questions_per_page`, по которым она работает), грепами по **установленному из архива** `olympiad-frontend.js` (постраничный `renderPage()`, `buildPages()`, баннер `wpo-group-banner`, таймер группы, отключение полей просроченной группы, сбор значений анкеты) и сохранением одиночного режима — все HTTP-проверки 1.0.20 проходили через тот же раннер после правок (24/24).

Серверная часть при этом проверена полностью: порядок и группировка выдаваемых заданий, отметки открытия групп, обнуление ответов просроченной группы, значения анкеты в БД, протоколе, REST и webhook. При истечении лимита группы клиент лишь подсказывает участнику — решение о зачёте принимает сервер, поэтому отсутствие браузерной проверки не влияет на корректность оценок.
